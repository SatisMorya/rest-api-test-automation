# API Documentation: GoRest v2 Users

**Base URL:** `https://gorest.co.in/public/v2`
**Auth:** `Authorization: Bearer <token>` (needed for POST, PUT, DELETE; reading public users needs no token).
Source: GoRest public documentation and community Q&A. Behaviour should be confirmed with a live run.

## User object
| Field | Type | Allowed values |
|---|---|---|
| id | integer | generated by the server |
| name | string | required |
| email | string | required, valid format, unique |
| gender | string | `male`, `female` |
| status | string | `active`, `inactive` |

## Endpoints
| Method | Path | Success | Failure |
|---|---|---|---|
| GET | `/users` | 200 + array | |
| GET | `/users/{id}` | 200 + object | 404 |
| POST | `/users` | 201 + object | 422 |
| PUT | `/users/{id}` | 200 + object | 404, 422 |
| DELETE | `/users/{id}` | 204, no body | 404 |

## Error formats
- 422: `[{"field": "email", "message": "has already been taken"}]`
- 404: `{"message": "Resource not found"}`

## Known quirks
- Email must be unique; the framework generates unique emails.
- Data is public and shared; the framework creates and deletes its own users.
- Rate limits apply; keep runs small.
